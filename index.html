  10. SWA calls this after every sign-in and puts what it returns into the user's roles. It is the only way roles reach the API: the x-ms-client-principal header the API sees does not carry Entra app-role claims.

    // api/src/functions/GetRoles.js
const { app } = require('@azure/functions');
const KNOWN = ['sales', 'install', 'admin'];
app.http('GetRoles', { methods: ['POST'], authLevel: 'anonymous', handler: async (req, ctx) => {
  const body = await req.json();
  ctx.log('GetRoles payload', JSON.stringify(body));   // remove after the first successful sign-in
  const roles = (body.claims || [])
    .filter(c => c.typ === 'roles' && KNOWN.includes(c.val))
    .map(c => c.val);
  return { jsonBody: { roles } };
}});

    Role functions are marked preview in the docs. On the first deploy, read the logged payload in Application Insights and adjust the filter if the claim type differs.

Phase 2

Database and checklist template

8 to 12 h

  1. VS Code, SQL Server panel, Add Connection: server sql-eled-platform.database.windows.net, database eled-dev, authentication Microsoft Entra ID, Universal with MFA. Build and test everything against eled-dev; only pipelines touch eled-prod.

  2. mkdir -p db/migrations db/seed && cd db && npm init -y && npm i mssql

    db/migrate.js signs in with whatever az login (your Mac) or the pipeline's Azure CLI step provides, applies every numbered .sql file not yet in SchemaVersion, and splits files on GO lines:

    // node db/migrate.js eled-dev
const sql = require('mssql'); const fs = require('fs'); const path = require('path');
const cfg = { server: 'sql-eled-platform.database.windows.net', database: process.argv[2],
  authentication: { type: 'azure-active-directory-default' }, options: { encrypt: true } };
(async () => {
  const pool = await sql.connect(cfg);
  await pool.query(`IF OBJECT_ID('dbo.SchemaVersion') IS NULL
    CREATE TABLE dbo.SchemaVersion (Version int PRIMARY KEY, FileName nvarchar(200), AppliedAt datetime2 DEFAULT sysutcdatetime())`);
  const done = new Set((await pool.query('SELECT Version FROM dbo.SchemaVersion')).recordset.map(r => r.Version));
  const dir = path.join(__dirname, 'migrations');
  for (const f of fs.readdirSync(dir).filter(f => /^\d{3}_.*\.sql$/.test(f)).sort()) {
    const v = parseInt(f); if (done.has(v)) continue;
    const text = fs.readFileSync(path.join(dir, f), 'utf8');
    const batches = text.split(/^\s*GO\s*$/im).filter(b => b.trim());
    const noTx = /^--\s*no-transaction/m.test(text);   // full-text DDL cannot run in a transaction
    const tx = noTx ? null : new sql.Transaction(pool); if (tx) await tx.begin();
    for (const b of batches) await (tx ? new sql.Request(tx) : pool.request()).batch(b);
    await (tx ? new sql.Request(tx) : pool.request()).input('v', v).input('f', f)
      .query('INSERT dbo.SchemaVersion(Version, FileName) VALUES (@v, @f)');
    if (tx) await tx.commit(); console.log('applied', f);
  }
  await pool.close();
})().catch(e => { console.error(e); process.exit(1); });

    Rule for the team: migrations only move forward. Never edit a file that has been applied; add a new one.
